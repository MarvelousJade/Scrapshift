# Remaining item behavior parity audit — 2026-10-20

## Scope and baseline

At commit `8246340`, the imported JSON contains 209 items and 50 characters. Their `conditionalEffects` use 43 distinct custom keys (the counts include unavailable but imported carriers). This pass compares interaction families among those imported effects against the supplied read-only Brotato source. It does not claim all item pairs, all acquisition orders or a human 20-wave run are covered. R25's 1,181 passing tests and native burn review are the prior checkpoint, not validation of the October 20 edits.

## Confirmed differences

1. **Lethal periodic self-damage skipped death cleanup.** `player.gd:844-850` applies periodic health loss through `take_damage`; lethal damage reaches the same death/cleanup callback as an ordinary hit. Scrapshift's `ConditionalEffects.TickConditionalEffects` set `Phase = Lost` directly, bypassing `BeginDeathCleanup`. It now calls that helper, matching the ordinary `RunRules.Hurt` path. Root focused-tested and committed this fix as `e4f0915` (16/16 passed). The survival track owns its regression tests and subsequent death cleanup logic.
2. **Character stat gain did not scale linked output.** In `linked_stats.gd:20-74`, every link is truncated before adding to `LinkedStats`; `LinkedStats` inherits `temp_stats.gd:get_stat`, which multiplies its accumulated result by `RunData.get_stat_gain`. Scrapshift previously added `LinkedStat` after multiplying the ordinary stat, leaving linked bonuses unscaled. `ConditionalEffects.LinkedStat` now applies the target stat gain after accumulation. The actual Renegade's `renegade_effect_1.tres` grants +10 raw Damage per distinct common item; `renegade_effect_5.tres` gives −80% Damage gain. Thus each distinct common item adds +2 effective Damage. `ItemsRemainingParityTests` checks Coffee/Beanie acquisition, duplicate Coffee, and removal. **Focused validation passed16/16, zero failures/skips, exit0 (`linked-stat-tests-attempt-3.xml`).** Two preceding attempts exposed fixture assumptions: Coffee also contributes direct -2 Damage per copy, and after removing all Coffee only the Beanie common-item link remains. Expectations were corrected against the actual catalog; the production gain correction was retained. Native combined behavior remains pending.

3. **Pet-linked stats used live actor count.** `linked_stats.gd:39` calls `RunData.get_nb_pets`; `run_data.gd:1528-1535` counts registered pet effects, the Jellyshield scalar and structure effects flagged `is_pet`. Scrapshift instead used the live `PetCount`, which varies as actors spawn or die. `ConditionalEffects.LinkSource` now counts registered effects. `PetLinkParityTests` uses the real weaponless Beast Master with five starting pet items and checks live-count independence, removal/reacquisition, Jellyshield and Wandering Bot. An initial test exposed the imported Jellyshield presentation entry, which has an empty pet kind and must be counted through `jellyshield_count` only. Root focused-tested the corrected filter (`pet-link-tests-attempt-2.xml`: 10/10 passed) and committed it as `f9b7069`.

## Registered pet-count correction

`run_data.gd:get_nb_pets` counts registered pet-effect entries, Jellyshield's scalar count and structures flagged as pets. It does not count live actors. Beast Master's Speed link now uses that source inventory count; live actor death/multiplicity does not change the bonus. Empty serialized presentation-only PetSpec entries are excluded so Jellyshield is not counted twice. The real Beast Master, dog removal/reacquisition, Jellyshield and Wandering Bot case passed alongside nine related cases: **10/10**, no failures/skips, exit0 (`pet-link-tests-attempt-2.xml`,0.7100671s). The preserved first attempt caught the empty presentation entry double count. Native combination coverage remains pending.
