# Static item-pair oracle — 2026-10-20

## Purpose and bound

The supplied source's `RunData.add_item` applies each item effect and resets its stat cache (`singletons/run_data.gd:916-926`, `1244-1268`). `Utils.get_stat` combines permanent, temporary and linked stat sources (`singletons/utils.gd:461-466`). The export scripts measure the same 16 primary stat keys after acquiring imported items on Well-Rounded with a tier-I pistol at the first-wave, full-health **intermission** state. The original fixture has no live Player scene; `entities/units/player/player.gd:190-191,215-266` therefore never applies movement-driven temporary stats. The Unity exporter sets its fixture-only phase to Shop before acquiring items so those bonuses are likewise inactive. This is a finite static-stat check; it cannot establish timed effects, chance triggers, enemy interactions, sound, visuals, shop pools or every state. An exported difference requires source triage before a production change.

`scripts/item_pair_cases.py` starts with an empty baseline and single-item probes, then adds 30 representative pairs in preflight mode. Its all mode covers the 209 imported item IDs: 1 baseline + 209 singles + 21,736 distinct pairs + 209 doubles = 22,155 cases. Order is sorted and fixed. The pair portion intentionally does not cover both acquisition orders, three-item combinations or characters with different stat gains; those are separate potential expansions after the preflight is credible.

## Isolated run setup

1. Generate `cases-preflight.jsonl` with `scripts/item_pair_cases.py --mode preflight --output <absolute path>`. Use `--mode all` only after a successful preflight.
2. Copy `scripts/reference_item_pair_oracle.gd` into the isolated **writable reference clone**. Register it as an autoload in that clone's `project.godot` after the existing singleton autoloads, for example `ItemPairOracle="*res://reference_item_pair_oracle.gd"`. Keep the supplied `E:/UnityProjects/brotato-(3.x)` checkout read-only. Set `SCRAPSHIFT_ORACLE_CASES` and `SCRAPSHIFT_ORACLE_OUTPUT` to absolute paths and launch the clone through its Godot executable in headless mode. The script writes JSONL and quits; `ITEM_ORACLE_REFERENCE_DONE` plus process exit zero are required.
3. Copy the current source to the established isolated Unity validation clone, verify the copied file hashes, then launch batchmode with `-executeMethod Scrapshift.Editor.ItemPairOracle.Export --item-oracle-cases <absolute path> --item-oracle-output <absolute path>`. Require `ITEM_ORACLE_UNITY_DONE` and process exit zero.
4. Run `scripts/compare_item_pair_oracle.py --cases <cases> --reference <reference JSONL> --unity <Unity JSONL> --output <report JSON>`. It requires identical case sets, compares the ordered 16-stat vectors to `1e-4` absolute tolerance, records input SHA-256 hashes, reports export errors separately and preserves the first 100 stat differences. Preserve raw JSONL, logs, manifest and mismatch report even if comparison fails.

Original and Unity exporters use actual item acquisition functions, not copied formulas. They intentionally use their respective runtime implementations; an exporter error, missing ID or baseline mismatch should be investigated before scaling to all 21,945 cases. A clean static result would close this one finite vector/state/order matrix only.

## Current result

The first 30-pair preflight used the original script version without baseline or singles. The isolated Godot exporter completed 30 rows and exited zero; the Unity exporter completed 30 rows. `artifacts/parity-remaining-2026-10-20/item-oracle-preflight/comparison.json` reports **30 compared, zero export errors and zero static-stat mismatches**, with hashes for all three inputs.

The first expanded all-item run exported 22,155 cases and found 627 vector mismatches, confined to Barricade Armor, Chameleon Dodge and Statue Attack Speed: 210/210/211 affected cases. The extra Attack Speed row is Chameleon plus Retromations Hoodie: the Hoodie's +2 Attack Speed per Dodge link multiplied Chameleon's +20 standing Dodge into a +40 linked difference. Source `entities/units/player/player.gd:190-191,215-266` applies those standing bonuses only through the live Player, which the Godot exporter did not instantiate. The Unity fixture had been left in Playing and automatically included them. This was a **fixture context mismatch**, not evidence for a production change; the raw `item-oracle-all/comparison.json` and Unity JSONL remain preserved.

The corrected Unity exporter used the matching intermission state. `artifacts/parity-remaining-2026-10-20/item-oracle-all/comparison-attempt-2.json` reports **22,155/22,155 compared, zero export errors, zero static-stat mismatches**, using the unchanged source/case JSONL and new `unity-attempt-2.jsonl`; the report records SHA-256 for each input. `unity-attempt-2.log` contains `ITEM_ORACLE_UNITY_DONE 22155`, and the headless Unity process exited zero. The isolated Godot process had completed its 22,155 rows with exit zero; it logged shutdown resource warnings after its done marker. These results close the stated 16-stat, one-character, full-health intermission matrix, including all distinct item pairs and double copies in the 209-item import. They do not validate in-wave standing effects, reverse acquisition order, three-item combinations, other character gains, timed/proc combat effects or native presentation.
