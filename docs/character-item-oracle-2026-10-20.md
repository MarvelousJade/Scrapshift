# Character by item static oracle — 2026-10-20

## Scope

This extends the [item-pair intermission oracle](item-pair-oracle-2026-10-20.md) to character modifiers and starting loadouts. `scripts/character_item_cases.py` generates a bounded five-character/five-item preflight (30 rows including baselines), then all 50 imported characters crossed with each of 209 single items plus one baseline per character: **10,500 cases**. Each case compares the same ordered 16 primary stat keys at full health, in an intermission with no live Player movement. The reference fixture calls `RunData.add_character`, adds the selected weapon or one selected starting item, then calls `RunData.add_starting_items_and_weapons`; the Unity fixture calls `RunRules.Start` with the corresponding imported profile and selected choice. Both then acquire the case item through their runtime item functions.

The generator chooses the first **available** imported starting weapon at the character minimum tier. For a character with item choices it chooses the first selectable item. The reference exporter maps imported `cactus_mace` to source `cacti_club` for six characters whose first starting weapon uses that renamed ID; the selected tier-I resource has `my_id = "weapon_cacti_club_1"`. The preflight must verify the selected resources and starting loadout before interpreting any stat differences. Beast Master is weaponless and chooses one of four pet items; its `starting_item` effect separately grants Lootworm. Source `ui/menus/run/weapon_selection.gd:121-155` and `singletons/run_data.gd:906-925,1618-1645` control these paths; this fixture should remain in a writable clone of the supplied reference.

The matrix measures static stat composition for one extra item per character. It does not cover pairwise items under every character, in-wave movement or health thresholds, random effects, timed triggers, combat or shop eligibility. A comparison mismatch requires investigation of setup, imported data and source behavior before a production edit.

## Isolated execution

1. Generate a new case file with `scripts/character_item_cases.py --mode preflight --output <absolute path>`; use `--mode all` after setup validation.
2. Copy `scripts/reference_character_item_oracle.gd` into the isolated read-write Godot clone and register it as an autoload **instead of** the pair oracle. Set `SCRAPSHIFT_ORACLE_CASES` and `SCRAPSHIFT_ORACLE_OUTPUT` to absolute paths, launch headless, and require `CHARACTER_ORACLE_REFERENCE_DONE <count>` plus exit zero.
3. Copy current project source into the isolated Unity clone and invoke `-executeMethod Scrapshift.Editor.CharacterItemOracle.Export --item-oracle-cases <cases> --item-oracle-output <Unity JSONL>`. Require `CHARACTER_ORACLE_UNITY_DONE <count>` and exit zero.
4. Reuse `scripts/compare_item_pair_oracle.py` with `--cases`, `--reference`, `--unity`, `--output`, and `--scope "50 characters by baseline plus one acquired item, static 16-stat intermission"`. Preserve source and Unity JSONL, process logs and SHA-256 report for both passing and failing runs.

The first preflight (before separating Beast Master's item choices) completed 30 source/Unity rows with no exporter errors. Its six Beast Master cases differed by +8 Unity Speed because the fixture omitted a selected item and the old Unity start granted all five pet items. Source audit established that the actual selection grants one of four choices plus automatic Lootworm; this drove the import/runtime correction. Preserve the first raw preflight.

The Beast Master baseline recorded three source inventory entries (character, Bonk Dog, Lootworm) and two Unity items (Bonk Dog, Lootworm), both with Speed 4. Focused editor tests in `starting-choice-tests.xml` passed **16/16**, zero failures/skips. The 22,155-case item-pair result applies only to Well-Rounded and should not be cited as validation of this matrix.

The first full matrix in `artifacts/parity-remaining-2026-10-20/character-oracle-all` exported all **10,500** rows on both sides. Its 210 Unity errors are One Arm rows: the generator chose Claw, which is unavailable in the imported catalog; Dagger is the first available choice. Of the remaining rows, **630 cases differ**, all in three characters: Saver 210 (`percent_damage` source +1), Streamer 210 (`percent_damage` source -2 and `speed` source -1), Technomage 210 (`elemental_damage` source +2). The normal Scrapshift run presenter already supplies 30; this was an oracle setup mismatch. The generator and Unity exporter now align these inputs, pending a fresh run.

Technomage exposed a production mismatch. Source `run_data.gd:982-990` applies the selected Wrench's effects; `effects/items/structure_effect.gd:21-22` registers its turret, and `run_data.gd:1519-1527` counts it alongside two character-granted Turrets. Focused `weapon-structure-tests.xml` passed **22/22**, zero failures/skips, exit zero. Earlier tests saying weapon structure effects were excluded have been corrected because source registration disproved that claim.

The corrected full matrix is preserved at `artifacts/parity-remaining-2026-10-20/character-oracle-all-attempt-2`. Godot and Unity exporters each reported `CHARACTER_ORACLE_*_DONE 10500` and process exit zero. Formal `comparison.json` reports **10,500/10,500 compared, zero exporter errors, zero static-stat mismatches**; it includes SHA-256 hashes for cases and both result files. This covers all 50 imported character baselines and each of their 209 single-item acquisitions with the eligible first starter, source-default 30 materials, and no live movement. It does not establish timed/proc effects, combat, item pairs under each character, other selectable starting weapons/items, shop pools, or human play behavior. ## Source-copy provenance

The final source receipt compares all3,816 original `.gd`, `.tres`, `.tscn` and `.godot` files against the isolated character-oracle clone:3,804 match and12 differ. `source-provenance.json` records every difference and a SHA-256 of the full local input manifest; `source.diff` preserves the reviewed changes. Differences are isolated save/log/profile paths, debug prints, fixture bootstrap/autoload registration, and the inherited scripted movement hook. The hook references the older ParityFixture but is never called in this no-live-Player stat exporter. The item resources, run/stat/effect implementations used for vectors remain byte-equal. This is not a claim of an untouched native project or image/audio equality.
